## Отсутствие перевода и отсутствие записи при сверке источника

В [translation_not_present.json](../reports/stage-a/translation_not_present.json)
перечислены все **1 942** пары ID/язык, отсутствующие в JSON. Это
`translation-not-present`, а не доказательство отсутствия перевода в мире или
в других источниках. Независимая сверка подтвердила, что все эти пары отсутствуют
также в соответствующих предоставленных `/all` (`saved_all_snapshot_present: false`).
EN не содержит `160625a`, `140812s`,
`110625a`, `050402s`, `840705w`. Поэтому EN не является достаточным единственным
эталоном. LV заканчивается 02.01.2019; отсутствие более новых записей ожидаемо
для этого снимка. Покрытие четырёх предоставленных тематических страниц проверено;
полнота живого сайта не утверждается.

`source-missing` в программе означает: запись найдена в предоставленной
сохранённой исходной странице, но не найдена в соответствующем языковом JSON.
По семи `/all` и четырём тематическим снимкам таких случаев **0**, и обратные
разности множеств относительно соответствующих языковых категорий также пусты.
Это ограничено предоставленными исходниками. Четыре записи вне тематических EN/HR
и 40 различий между EN/HR не смешиваются с пропусками импорта. Статус источников —
`VERIFIED_SOURCE_SNAPSHOT_COVERAGE` в
[sources.json](../reports/stage-a/sources.json).

## Воспроизведение

Команда с обоими оригинальными ZIP воспроизводит текущие отчёты:

```bash
python3 -m scripts.audit_stage_a \
  --source-zip research-sources/medjugorje_original_sources_seven.zip \
  --thematic-zip research-sources/medjugorje_thematic_en_hr_sources_audit_2026-10-23.zip \
  --out reports/stage-a
```

Код **0** означает проверенное покрытие предоставленных снимков, **не редакционное
утверждение**. Код **1** — нарушения или расхождения. Код **2** — неполный набор
источников/неподтверждённое покрытие. Недоступный тематический ZIP явно отклоняется;
положительный отчёт по отсутствующему файлу не создаётся. Запуск не делает сетевых запросов.

Для дополнительных тематических MHTML можно использовать локальный манифест
такого вида (пути относительно манифеста):

```json
{
  "sources": [
    {"language":"en", "category":"all", "path":"en-all.mhtml", "url":"https://www.medjugorje.ws/en/messages/all/"},
    {"language":"en", "category":"annual", "path":"en-annual.mhtml", "url":"https://www.medjugorje.ws/en/messages/annual/"}
  ]
}
```

Это пример, а не список реально полученных файлов. Команда после их получения:

```bash
python3 -m scripts.audit_stage_a --sources saved/sources.json --out research-output/stage-a-with-sources
```

Семь полных архивов и все четыре требуемых тематических снимка получены и сверены.
Дополнительных файлов для этой технической сверки не требуется. Тематические RU
или индивидуальные страницы могут потребоваться редактору для отдельных решений;
это не делает неполной проверку уже предоставленных снимков.

Сверщик фиксирует хеш MHTML, `Content-Location`, исходные заголовки и ближайшие
названия разделов, все ID и аномалии парсера; сравнивает дату, тип, slug, URL,
заголовок, текст, сегменты и хеш. Ссылки навигации не считаются сообщениями.
Несовпадение адреса или страница без датированных заголовков даёт непроверенный
статус, а не пустой архив. Для `/all` и каждой языковой тематической категории
построены обе разности множеств ID; тематический сверщик также проверяет группы
и навигацию. Данные не переписываются.
Заголовки в JSON доступны полностью в
[inventory.json](../reports/stage-a/inventory.json), по всем ID и имеющимся языкам.
