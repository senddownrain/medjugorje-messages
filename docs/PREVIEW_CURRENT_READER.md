## Подготовленное обновление после разрешения владельца

1. Собрать именно head этого PR через `npm run build:private` и повторить `npm run test:preview`. Включённые SHA исходных JSON в отчёте позволяют сверить снимок.
2. Через Sites снова проверить существующий project ID/audience; синхронизировать этот checkout штатным source helper. Секретов в клиенте или GitHub нет; временные credentials не сохранять.
3. Выполнить только owner-private deployment существующего сайта; сохранить политику `custom`, owner only. При несовпадении аудитории остановить публикацию. Автоматического GitHub→Sites деплоя нет.
4. До передачи URL проверить без авторизации **HTML, JSON, SW и assets**: отсутствие доступа. С авторизацией владельца проверить актуальные селекторы `#query`, `#language-button`, ровно четыре фильтра `#visionary/#message-type/#year/#month`; сопоставить дату/текст с JSON и head PR.

Для фактического обновления нужен явный ответ владельца. Это требование текущего задания; дополнительных секретов для подготовки не потребовалось.

## На Android после разрешённого обновления

Открыть прежний HTTPS-адрес в Chrome, войти аккаунтом владельца. Убедиться, что есть новый языковой лист и четыре фильтра. Выбрать язык, прочитать последнее послание, открыть поиск/результат, нажать Back и Forward, проверить тему и отсутствие боковой прокрутки. Затем установить PWA через меню Chrome и отдельно проверить режим полёта. Данные на уже авторизованном телефоне могут оставаться офлайн после выхода из ChatGPT до очистки хранилища Chrome.

Этот PR содержит политику кеша C. Оптимизированный кеш и lazy loading D находятся в отдельном PR; для их телефонной проверки нужен отдельный согласованный preview head D + настройки этого PR.
