## Отдельный план безопасного запуска #21

1. **До слияния:** обновить отдельную ветку относительно актуального main; сохранить отсутствие изменений восьми JSON и отсутствие deployment/import/auto-merge. Не смешивать с брендингом. Повторить unit/mock-тесты, проверить все workflow triggers и permissions. В PR — только тесты, без уведомлений из недоверенного кода; `issues:write` только отдельному доверенному notify-job, без `contents:write` и `pull_request_target`.
2. **Ручная read-only диагностика:** проверить точные документированные URL и robots/TLS на GitHub runner без обхода ограничений. В сохранённом отчёте #21 от 24.10 HR отвечает 200, WS — Cloudflare 403; локальная среда получает proxy CONNECT 403 до обоих сайтов. Это исторические наблюдения, не свежий результат этого релиза. WS 403 должен оставаться ERROR, а не «новых посланий нет». Не менять UA/IP для обхода.
3. **Проверить baseline:** source + language + GUID/permalink, устойчивые markers старых и закрытых Issues, fingerprints исправлений, повторный запуск без дублей, commit состояния только после успешной доставки, concurrency, частичные отказы и истечение кеша. Первый снимок — baseline; это не проверка исторической полноты. RSS имеет ограниченное окно, BE-feed не подключён; HR не доказывает наличие всех семи переводов.
4. **Отдельное решение владельца:** выбрать источники и допустимые пробелы, разрешить только уведомления-кандидаты, затем выполнить один ручной trusted запуск с проверкой Summary/artifact и дедупликации. Расписание новой ветки включать только после этого решения и успешной проверки. Настроить понятное уведомление об ошибке/истечении baseline.
5. **Импорт — отдельная будущая задача:** каждый кандидат должен пройти ручную сверку источника, даты, типа и языка, полного текста и редакционного статуса. Переводы рассматриваются независимо; отсутствие перевода не заменяется чужим текстом. Исправления — отдельным PR с SHA/diff восьми JSON и явным редакционным утверждением. Никакого автоматического импорта, объединения переводов, утверждения атрибуций или слияния PR.

В текущем main уже существуют старые scheduled watchers, создающие только Issues-кандидаты. Их triggers и permissions этим релизом **не меняются**; новое расписание #21 и автоматический импорт не включены. Решение о замене либо отключении старых watchers нужно принять вместе с запуском #21, чтобы не получить параллельные дубли уведомлений.
