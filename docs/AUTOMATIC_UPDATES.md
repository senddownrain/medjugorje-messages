# Автоматическое обновление посланий

Реализован и испытан реальный автоматический импорт в изолированную базу: RU, UK, HR, SK и EN за **25 октября 2026**. Production-публикация **выключена**; main и восемь исходных JSON этим PR не изменены.

[PR #31](https://github.com/senddownrain/medjugorje-messages/pull/31) включает PR #27 поверх актуального main с мониторингом #21. Отдельно сливать #27 не требуется. Подтверждение владельца от 25.10.2026 разрешает автоматическое получение и публичную публикацию новых переводов на всех семи языках с указанием источника. Ручного утверждения каждого поддерживаемого послания нет.

## Реальный прогон

[CI с пятью переводами и повторами](https://github.com/senddownrain/medjugorje-messages/actions/runs/40240839793):

- Одно новое официальное monthly-послание `261025m`; RU/UK/HR/EN/SK добавлены независимо.
- Повтор того же запуска: **0 добавлений**, байты базы совпадают.
- Последовательные независимые языковые запуски дают ту же базу, что совместный запуск.
- Имитация исправления старого текста источником заблокирована; сохранённая база не меняется.
- Append-only, целостность данных, воспроизводимые metadata, поиск/Worker, production build, mobile browser и offline/PWA update проверки — PASS.
- Историческая база сохранилась. Новые записи остались `verified=false` / `source_import_unreviewed`.

EN получен из полного официального архива, а не RSS-анонса. Официальный источник не сообщает время публикации: `published_at=null`, причина записана отдельно. Время обнаружения не подменяет дату публикации.

У HR шаблон HTML ошибочно объявляет `lang=en`, хотя маршрут `/hr/`, заголовки и текст хорватские. Исключение привязано к этому подтверждённому маршруту и evidence; независимое определение языка самого текста остаётся обязательным. Английский текст в HR карточке не проходит тест.

Текущий подтверждённый автоматический тип — **monthly**. Уникальная дата + буквальная метка `Monthly` в официальной записи задаёт canonical ID. Визионер по календарю не назначается. Несколько секций одной даты, annual/special и спорная атрибуция остаются заблокированы, пока не реализован доказанный соответствующий адаптер. Это ограничение реальной реализации, а не обещание полной поддержки всех видов явлений.

Ленты — ограниченное окно обнаружения: запись, не попавшая в RSS, может быть пропущена. Подтверждённый официальный ID сохраняется с provenance; community-перевод из проверяемого RSS использует сохранённую идентичность, даже если дата ушла из текущего официального окна. Полнотекстовые EN/HR адаптеры читают текущую страницу архива, а не все исторические годы. Новые официальные неоднозначности не перекрываются старым кешем. Community-публикации до запуска 25.10.2026 не бэкфиллятся. Для позднего перевода проверяется дата его публикации, а не только дата послания: новый перевод старого послания не отбрасывается из-за старой даты. В официальном архиве без published_at текущий подбор ограничен карточками начиная с 25.10.2026.

Community EN `/amp` ссылки возвращают 404; обычные канонические страницы доступны, но действующий импорт EN использует официальный архив. `medjugorje.ws` после известного 403 не обходится. У BE текущий независимый перевод не подтверждён. Никаких машинных переводов или языковых подстановок.

## Как устроена защита

`Autonomous message updates` выполняет обнаружение → получение полного HTML → проверку → изолированную базу → append-only → все тесты → отдельные commit/build/deploy jobs.

Для каждого нового перевода хранятся источник и прямая ссылка, source ID, дата послания, независимая дата публикации или явное отсутствие, SHA-256 исходных байтов и текста, языковая проверка, официальный identity evidence, fingerprint политики и время импорта. Цитата сохраняется с пунктуацией источника; примечание об одобрении Церкви хранится отдельно от текста.

Проверяется robots для каждого endpoint, HTTPS origin, HTTP 200 без неутверждённых redirects, единственность полного тела и заголовка, явная дата, начало/конец цитаты, признаки усечения, язык HTML и самого текста через закреплённый langid. HTTP 403/robots/timeout не выдаются за «новых нет». Ошибка кандидата не переписывает всю базу и не отменяет допустимые языки.

Существующие строки неизменны, включая пунктуацию, сегменты, метаданные и атрибуцию. Повторный текст и source identity блокируются; одинаковый URL официального архива допустим для разных подтверждённых source ID. Финальный gate — исходный `check_append_only_updates.py` из #27.

Сборщик metadata фиксирует хеши каждого исторического record. Исторические audit tests проверяют реконструированный снимок, совпадающий с исходными SHA целых файлов; новые записи проверяются отдельно. Добавление записи больше не ломает проверки из-за фиксированного числа 899. Неизвестная редакционная достоверность не становится `verified` от технического PASS.

Release jobs выполняются только после успешной проверки. После commit с неудачным deploy следующий запуск сравнивает SHA восьми файлов с публичным release.json и выпускает уже сохранённые данные, даже при нуле новых записей. Совпадающая опубликованная база не создаёт новый commit/deploy; artifacts поддерживают overwrite при повторе Actions run. Commit содержит только data/derived, push без force отвергает гонку main. Собирается точный новый коммит. Два Pages workflows используют общий deployment lock и отвергают устаревший SHA. После успешного публичного SHA-check записывается компактный журнал последних 20 публикаций.

## Бейдж «Новое»

Manifest содержит ID новых импортированных переводов по языкам. При первом запуске текущий набор становится исходным состоянием без бейджей. Следующие новые пары язык/ID сохраняются в localStorage, переживают обновление PWA и offline. Состояние установленной версии до появления бейджа мигрирует из предыдущего SW manifest; первая установка остаётся без исторических отметок. Старый кеш не возвращает уже снятый бейдж; поздний SK не сбрасывает прочитанный RU.

Открытие из списка снимает бейдж. Главная уже показывает полный последний текст, поэтому её «Новое» снимается нажатием на сам бейдж или открытием записи из списка. Новых окон нет. При запрете localStorage состояние действует только в текущей сессии.

Проверено production Chromium: главная/список, light/dark, 320/390 px, повторный offline-запуск, отдельный поздний перевод. Физический Android — **NOT TESTED**.

## Журнал с телефона

1. GitHub → Actions → **Autonomous message updates** → запуск → Summary.
2. Artifact **automatic-update-audit**: audit.json, ошибки/пропуски/даты, browser screenshots, offline results. Полного текста посланий в audit нет.
3. На main artifact **automatic-update-result** дополняет аудит итогом commit/deploy/public-check и ссылками.
4. Issues → одна «Автообновления: состояние источников и выпуска»: обновляется тело, без повторных комментариев; ошибки всех release jobs учитываются.
5. Code → [reports/updates/latest-successes.json](../reports/updates/latest-successes.json): только реально опубликованные обновления. Сейчас пуст, поскольку production не запускался. [Live dry-run](../reports/updates/live-dry-run-2026-10-25.json) показывает проверенный импорт.

Репозиторий фактически публичный, несмотря на старую отметку PRIVATE в AGENTS/CLAUDE. Полный HTML не сохраняется в публичных artifacts; остаются SHA, ссылки и безопасная диагностика. Ранее созданные полностраничные inspection artifacts удаляются отдельным исправляющим job, ограниченным PR #31. В приватном репозитории можно хранить разрешённые raw snapshots с коротким сроком. Метаданные источников — artifact `source-inspection-metadata`.

## Что нужно до production

Production имеет три независимых условия: готовность в `reports/updates/readiness.json`, repository variable `AUTOMATIC_MESSAGES_PRODUCTION=true`, запуск на main. `workflow_dispatch publish=true` не обходит проверки. После единовременного включения расписание 06:35/18:35 UTC работает без владельца; недоступный язык остаётся заблокированным.

Осталось проверить обновление **установленной Android PWA** и первый настоящий commit/deploy/public verification. Публичный release в этой задаче не выполнялся. Неподтверждённые языки не требуют включения для выпуска работающих независимых языков.

Android: открыть установленную PWA онлайн и сохранить RU/SK, после разрешённого тестового выпуска принять штатное обновление; проверить дату, источник и «Новое»; открыть послание, включить авиарежим, полностью закрыть/открыть приложение. Текст должен остаться, бейдж прочитанного не вернуться; поздний перевод другого языка отмечается отдельно. Desktop Chromium и зелёный CI не заменяют эту проверку.
