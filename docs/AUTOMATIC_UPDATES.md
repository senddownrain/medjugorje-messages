# Автоматические обновления: состояние реализации

Production **выключен**. Полноценный автономный импорт с реальных сайтов пока **не готов**: сетевой доступ, точное выделение цитат и официальная идентичность новых записей ещё не проверены. Синтетические тесты не заменяют этот этап.

Ветка включает все шесть файлов PR #27 поверх main (`a80549c`), без редактирования исходных проверок. PR #21 остаётся действующим мониторингом; новый конвейер использует его parsers/robots/discovery и не создаёт второй набор уведомлений о каждой публикации.

## Что реализовано

- Отдельный `Autonomous message updates`: PR/manual — проверка без публикации; расписание после merge — проверка каждые 12 часов. Публикация имеет отдельные обязательные блокировки.
- RSS используется только для обнаружения. Полнотекстовый HTML-адаптер требует разрешённого origin, robots, прямого HTTP 200, подтверждённых селекторов полного текста, буквальных границ цитаты, явной даты послания, HTML языка и timezone публикации. Переадресация, 403 и robots-запрет останавливают получение. Селекторы реальных сайтов не выдуманы: пока `null`, адаптеры выключены.
- Полученный текст, URL, source ID, дата послания, независимая дата перевода, SHA-256 исходных байтов/текста/политики и официальное evidence хранятся в provenance. `technical_status=validated` не меняет `verified=false`; редакционный статус `source_import_unreviewed`.
- Изолированная база-кандидат. Ошибки одного кандидата не отменяют другие допустимые переводы. Старые записи неизменны, повторные тексты/ID/source identity отклоняются, изменения источником передаются на ручную проверку.
- Финальный append-only gate из PR #27, проверка данных, воспроизводимые метаданные, поиск/Worker, сборка и browser/offline проверки предшествуют commit/publish. Ошибка шага исключает все зависящие от него release jobs. Push без force отвергает гонку с изменившимся main.
- Сборщик поиска больше не привязан только к хешу целого исторического файла: `update-integrity-baseline.json` фиксирует SHA каждого исторического record и подтверждённых полей индекса. Новые записи требуют provenance; существующая тематическая доказательная база и редакционные статусы сохраняются.
- Production jobs: commit проверенных data/derived → сборка точного коммита → Pages artifact → deploy → проверка публичного SHA → компактный журнал. Pages deployments обоих workflows сериализованы и отвергают устаревший коммит.
- Журнал `latest-successes.json` обновляется только после успешной публикации и проверки. Полные тексты не попадают в audit/summary/health issue. Данные-кандидаты остаются отдельным краткоживущим artifact только trusted main.
- Одна health Issue, обновляемое тело без повторяющихся комментариев. При восстановлении закрывается. PR не получает write token.

## Официальная идентичность — оставшийся существенный этап

Действующий официальный watcher достоверно обнаруживает даты и fingerprint секций, но не доказывает уникальный ID/тип/визионера. `research/official-update-identities.json` пока пуст. Движок импорта требует подтверждённого сопоставления source ID с canonical ID и совпадения хеша официальной секции текущего запуска. Новые даты не превращаются в ID и атрибуции по календарю.

Текущая реализация поддерживает проверенные сопоставления и поздние переводы, **но не умеет автономно подтверждать идентичность будущих официальных записей**. До реализации и испытания такого адаптера полностью автономную публикацию включать нельзя. Это явная блокировка, а не скрытый ручной шаг в якобы готовом pipeline.

## Бейдж «Новое»

Manifest содержит компактные списки ID импортированных переводов по языкам. На первом запуске они принимаются за исходное состояние без бейджей. При следующих посещениях новые пары язык/ID становятся непрочитанными; localStorage хранит их между обновлениями и офлайн-запусками. Старый офлайн manifest не сбрасывает прочитанное, поздний перевод другого языка учитывается отдельно.

В списке открытие послания снимает бейдж. Главная уже показывает полный текст последнего послания, поэтому её бейдж остаётся до нажатия «Новое» (явная отметка прочтения) или открытия записи из списка. Никаких новых окон. При запрете localStorage состояние действует только в текущей сессии.
