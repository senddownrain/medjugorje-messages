## Поведение

- Открытие приложения: полное последнее доступное послание **с текстом** выбранного
  языка, заметный поиск, ниже недавние записи. Ограничения только monthly больше нет.
- Нажатие на поиск открывает результаты на том же основном экране; отдельного
  пользовательского раздела «Архив» нет. Фильтры изначально свёрнуты.
- По умолчанию `availability:present`: только присутствующие записи языка.
  Отдельный переключатель включает записи без перевода. Пустая запись, контекст
  без текста и отсутствующий перевод различаются; автоматического fallback нет.
- Все шесть получателей и «Не указан», независимые серия/тип, год, точная дата,
  включительный период; слова AND и фразы, настройка диакритики, сброс.
  Фильтры работают без текста. Карточка содержит дату, получателя, серию/тип,
  короткий фрагмент и безопасный `<mark>` через интерполяцию Vue.
- Полный текст и исходные контекстные сегменты выводятся отдельно, без изменения
  слов. Контекст UK `230225m` не выдан за текст послания. Источники открываются
  по неизменённым исходным URL. Доступные языки можно выбрать вручную, сохранив ID.
- Восемь атрибуций остаются `pending` с видимой пометкой «ожидает утверждения»;
  остальные 154 неизвестных не получают адресата. Модель B не изменена.
- В верхней панели справа ровно две кнопки: код языка и солнце/луна.
  Нижний лист Vuetify содержит независимые язык UI/посланий и системную тему.
  UI переведён на все семь языков. Существующие название и восьмилучевой знак
  сохранены; знак монохромный, без цветного emoji. Новой иллюстрации/иконки нет.

## Worker, ошибки и история

Пользовательский поиск использует настоящий `createSearchWorker()` из B.
`WorkerSearch` сериализует загрузку активного корпуса и запросы, пропускает
устаревшие ожидающие задачи и проверяет поколение результата/ошибки перед
передачей в UI. Пока запрос выполняется, прежние карточки не выдаются за новый
результат: есть `aria-busy`, статус подготовки и затем актуальный счётчик.
Нет debounce или сетевого поиска. Инициализация, ошибки загрузки Worker,
повторная попытка и `dispose()` проверены. Основной поток только проецирует ID,
готовит видимые фрагменты и рендерит безопасную подсветку.

Перед открытием послания сохраняется снимок списка в `history.state`: запрос,
фильтры, язык посланий, режим, диакритика, включение пропусков, раскрытие фильтров,
лимит/пагинация, scroll и ID фокуса. Чтение получает отдельную запись истории.
Back/Forward, кнопка «Назад» и refresh восстанавливают состояние. Системная
кнопка Back браузера использует ту же историю, но физический Android не запускался.
`#message/<id>` сохранён, включая недоступные переводы и refresh; `#archive`
открывает новый единый поиск. Дополнительного раздела с таким названием нет.

## Граница с D и приватным превью

`vite.config.js`, `src/main.js`, `scripts/stage-data.mjs` и существующий workflow
приватной сборки не менялись. Конфигурация PR #15 не копировалась. Загрузчик
сохраняет прежние required `index/ru/be/uk`, затем optional `hr/en/sk/lv`.
Браузер подтвердил восемь исходных запросов при старте и отсутствие новых запросов
данных при поиске/сменах языка. Экономия трафика ещё **не реализована**.

Производная модель импортируется в приложение, Worker включён в production assets.
Поэтому хеши/размеры собранных JS и автоматически сгенерированный precache manifest
меняются естественно вместе с кодом; **политика** кеша, staging и регистрация SW
не менялись. Основной JS вырос до ~1,26 MB (~162 KB gzip); Vite предупреждает о
чанке >500 KB. В D нужно измерять весь старт, передачу, память и поведение кешей,
а затем выделять компактную модель и загружать языки по запросу. Эти изменения
здесь намеренно не выполняются. Замеры скорости движка B остаются в
[SEARCH_V2_PERFORMANCE.md](SEARCH_V2_PERFORMANCE.md); время от ввода до отрисовки C
на физическом телефоне не измерено.

## Воспроизведение

```bash
npm run check:search-metadata
npm run test:search
python3 -m unittest discover -s tests -v
npm run check:data
npm run test:search:browser
npm run build
npm run test:ui:browser
```

Нужны npm-зависимости, Python Playwright и Chromium. UI-скрипт использует системный
Chromium из PATH либо установленный Playwright Chromium, запускает и завершает
локальный preview сам. В CI расширен отдельный workflow поиска; отчёт и снимки
загружаются в приватный Actions artifact `reader-ui-review` на семь дней.
Снимки для текущей оценки также закоммичены в приватный репозиторий.

## Как оценить с Android без публикации

1. Открыть этот Draft PR в GitHub и перейти в [галерею](STAGE_C_SCREENSHOTS.md).
2. Посмотреть RU 390 light/dark, RU 320, языковой лист, фильтры и недоступный перевод;
   затем сравнить локализации по ссылкам. PNG можно открыть отдельно и увеличить.
3. Отметить желаемые изменения размеров, интервалов, цветов и карточек в ревью PR.
   Действующий сайт пока не обновлён; интерактивная проверка на телефоне потребует
   отдельно разрешённого приватного превью. Здесь такое превью не создавалось.

Отдельные решения владельца: визуальная оценка C и окончательное утверждение
восьми `pending`-атрибуций. Они не утверждаются этим PR автоматически.
