## Модель и редакционные статусы

`derived/search-metadata.json` детерминированно строится из восьми исходных JSON
и проверенных отчётов Stage A. Генератор проверяет хеши всех восьми входов по
аудиту. В исходный `data/` он не пишет. В модели 899 ID и 917 ссылок на доказательства.
Формат одной записи:

```js
{
  id: '850114w', date: '1985-01-14',
  type: { value: 'weekly', source_status: 'source_confirmed',
          editorial_status: 'unreviewed', evidence: ['index:850114w'] },
  visionary: { value: 'vicka', source_status: 'source_confirmed',
               editorial_status: 'pending', evidence: ['proposal:850114w'] },
  series: { value: null, source_status: 'unknown',
            editorial_status: 'unreviewed', evidence: ['index:850114w'] },
  availability: { /* по каждому из семи языков */ }
}
```

`visionary`, `type` и `series` независимы. Восемь подтверждённых источниками
кандидатур используются со статусом `pending`, никогда `approved`.
Исходное `verified` не повышается. Рекомендация ревью не считается утверждением владельца.
Унаследованные атрибуции без самостоятельного группового доказательства отмечены
`legacy_import` / `unreviewed`, а не объявлены заново подтверждёнными.
Для каждого факта есть статус и ссылки на индекс, исходный permalink, JSON Pointer,
хеш MHTML/отчёта, либо точные цитаты предложения. Все указатели проверяются тестом.

Распределение получателей в производной модели: Мария 480, Мирьяна 211,
Яков 30, Иванка 20, Иван 3, Вицка 1, неизвестно 154. Все 154 остаются `null`.
Ровно 258 ID имеют серию по подтверждённым тематическим группам:
`ivanka_annual`, `jakov_annual`, `mirjana_annual`, `ivan_special`,
`marija_special`, `mirjana_second_day`. У остальных 641 серия `null`.
Серии для monthly/weekly не выведены из календаря или суффикса ID.
Четыре исключения `110625a`, `160625a`, `140812s`, `050402s` сохранены;
их отсутствие в тематических EN/HR не устраняется вымышленной серией.

Доказательства вынесены в общий словарь `evidence`; факты содержат ссылки.
`inputs` хранит SHA-256 исходников и отчётов. `npm run check:search-metadata`
отклоняет устаревшую модель, не перезаписывая её. Генератор намеренно отклоняет
неожиданное применение/утверждение предложений A: владельческое решение требует
явного изменения редакционной политики отдельной проверкой, а не автоповышения статуса.

## API поиска

```js
import { SearchCatalog } from '../src/search/catalog.js';
import { SearchSession } from '../src/search/session.js';

// metadata — производная модель; archives — уже загруженные исходные файлы.
const catalog = new SearchCatalog(metadata, { ru, be, uk, hr, en, sk, lv });
const result = catalog.search('en', {
  query: '"dear children" peace', mode: 'words', foldDiacritics: true,
  filters: { year: 2020 }, offset: 0, limit: 35
});
// result.ids — все совпавшие канонические ID; rows — указанная страница, total — полный счётчик.
```

`searchIds(language, options)` возвращает все ID, новейшие первыми; одинаковые
даты упорядочены по ID. `search()` добавляет отображаемую страницу и сведения
о переводе. `highlights(id, language, query, options)` возвращает исходные поля
`title`, `message`, `context` с диапазонами UTF-16. `SearchHighlight.vue` выводит
их через интерполяцию и `<mark>`, без HTML-инъекции. `highlightParts()` подходит
для других рендереров с textContent. Не передавать строки в `v-html`/innerHTML.

В режиме `words` все слова обязательны; порядок свободный. Кавычки задают
непрерывную фразу, например `"dear children" peace`. Режим `phrase` ищет всю
строку как одну фразу. Это полные слова/фразы, без стемминга и автоперевода;
части слов не считаются отдельными словами. Фраза не пересекает границы полей.
Ищутся заголовок, текст послания и каждый контекстный сегмент выбранного языка.
Контекстный результат не превращается в текст послания (`UK 230225m` проверен).

Доступные фильтры (пропущенное поле означает «всё»):

- `visionary`: шесть имён либо `unattributed` для `null`.
- `series`: одна из шести подтверждённых серий либо `unattributed` для `null`.
- `type`, четырёхзначный `year`, `date`, включительные `dateFrom` / `dateTo`.
- `availability`: `all` (по умолчанию), `present`, `with_text`, `missing`.
- `reviewStatus`: `any`, `pending`, `unreviewed` для атрибуции получателя.
- `attributionPolicy`: `include_pending` (по умолчанию) либо `without_pending`.

Вторая политика рассматривает кандидата как неизвестного получателя при фильтрации,
но не удаляет запись. Например, Иван: 3 при include_pending, 0 при without_pending;
неизвестных соответственно 154 и 162. Без фильтра получателя остаются все 899 ID.
В строках результата всегда остаются исходный факт и `pendingAttribution`.
Неверные даты, обратный период и некорректная пагинация дают явную ошибку.

## Семь языков, пропуски и состояние

Нормализация использует NFC и Unicode lower case. По умолчанию снимается
латинская диакритика, в том числе HR/SK/LV; дополнительные соответствия:
`đ→d`, `ł→l`, `ø→o`, `ß→ss`. Это не транслитерация `đ→dj`.
`foldDiacritics:false` сохраняет диакритику. Кириллические `й`, `ё`, `ў`, `ї`
остаются отдельными буквами; NFD/NFC-эквиваленты и типографские апострофы
обрабатываются одинаково. Подсветка сохраняет исходные буквы, комбинируемые
знаки и позиции после emoji; строка не переписывается нормализованным вариантом.

Доступность каждого ID/языка: `with_text`, `context_only`, `no_message_text`,
`translation_not_present`. Исходный статус вроде `no_message_announced` остаётся
в `record.status`. Пропуск перевода и пустой текст — разные состояния.
Индекс метаданных содержит все 899 ID; фильтры без текста дают одинаковые ID
на любом языке. Все 1 942 отсутствующие пары переводов учтены, подстановок нет.
При текстовом запросе совпадение возможно только в выбранном языке.
Текстовый поиск по ещё не переданному архиву отклоняется явно; фильтры без текста
работают по метаданным всех 899 ID даже до передачи языкового JSON.
`projectResults()` отдельно сообщает `archiveLoaded`, если данные языка ещё не переданы.

```js
const session = new SearchSession(catalog, {
  language: 'uk', filters: { visionary: 'ivan' }, selectedId: '140812s', scrollTop: 390
});
session.setLanguage('en');
// Три ID сохраняются; выбранный 140812s остаётся, record === null, перевод отсутствует.
const restored = new SearchSession(catalog, JSON.parse(JSON.stringify(session.snapshot())));
```

Сохраняются запрос, режим, фильтры, выделенный ID и позиция списка. Текстовый
запрос при смене языка пересчитывается, поэтому его совпадения могут меняться.
Предыдущие ID с исходным языком остаются в `previousResults`;
`projectResults(previousIds, newLanguage)` сохраняет их порядок и честно показывает
отсутствующие переводы. Это проекция прежнего результата, не ложное совпадение
запроса в новом языке. `useMessageSearch()` даёт Vue shallow-ref адаптер без
маршрутизации, localStorage, fetch или изменения PWA-кеша.

## Worker и память

Индекс состоит из подготовленных строк и инвертированных списков слов;
метаданные фильтруются по отдельным фасетам. Нижний регистр всего текста
не вычисляется на каждом вводе. Карты исходных позиций строятся только для
показываемой подсветки. LRU по умолчанию удерживает два индекса (язык + режим
диакритики). `clearIndexes()` освобождает ссылки; исходные тексты не меняются.

Холодное построение при замедлении CPU заметно дольше запроса. Для C есть
`createSearchWorker(metadata)`: после `ready` передать
`loadLanguage(language, archive)`, затем `await searchIds(language, options)`.
Worker не скачивает данные и удерживает только текущий языковой корпус;
смена языка освобождает предыдущий корпус и индексы. RPC сопоставляет ответы
с запросами, передаёт ошибки и имеет `dispose()`. Основной поток может
проецировать возвращённые ID на уже имеющийся каталог. При асинхронном вводе
интерфейс C должен применять только ответ последнего актуального запроса.

| BE | `{query:'"Дарагія дзеці"'}` | Фраза по-белорусски |

| HR | `{query:'KRALJICA'}` | Unicode lower case |
| EN | `{query:'"dear children" peace', filters:{year:2020}}` | Фраза AND слово AND год |
| SK | `{query:'"Drahe deti"'}` | Диакритика снимается при сопоставлении |
| LV | `{query:'"Dargie berni"'}` | Находит исходное Dārgie bērni |

```bash
npm run build:search-metadata
npm run check:search-metadata
npm run test:search
python3 -m unittest discover -s tests -v

npm run build
python3 -m pip install playwright
npm run test:search:browser
npm run benchmark:search
npm run benchmark:search:browser
```

Последние две команды сохраняют измерения в `reports/stage-b/`.
Локальный Chromium берётся из PATH; в CI устанавливается Playwright Chromium.
Тесты проверяют оригинальные случаи, контекст, все семь языков, периоды,
кандидатуры/неизвестность, 899 ID, хеши, источники, отсутствие подмен перевода,
LRU, сериализацию состояния и XSS. Отдельный CI workflow не меняет workflow
приватной сборки PR #15. Подробные измерения — [SEARCH_V2_PERFORMANCE.md](SEARCH_V2_PERFORMANCE.md).
