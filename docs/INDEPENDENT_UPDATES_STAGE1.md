# Этап 1 задачи #25 — независимые языковые обновления, без импорта

**Статус:** подготовительные проверки на отдельной ветке. Ничего из этого пакета не добавляет послания в `data/`, не скачивает тексты с сайтов, не создаёт новых GitHub Issues, не переводит и не публикует их.

## Что установлено

- 7 независимых языков: RU / BE / UK / HR / EN / SK / LV. Наличие одной версии не является доказательством наличия остальных.
- Рабочие *наблюдатели* (PR #21): официальный **англоязычный** архив medjugorje.hr (даты и видимые EN-разделы), а также RSS-метаданные RU, UK, SK, LV, EN (пять сайтов Light of Mary). Эти пять RSS были доступны с GitHub Actions 24.10.2026; это **не означает**, что можно автоматически забирать полные тексты.
- Для **BE и HR нет подтверждённого отдельного актуального источника**, удовлетворяющего условиям автоматического чтения. Исторические сохранённые HTML/MHTML не дают разрешения на новый автоматический импорт; EN-архив нельзя считать хорватским.
- Исторический `medjugorje.ws` отвечал 403 Cloudflare в GitHub Actions. Не обходить запрет; не представлять ошибку как «новых текстов нет». Сохранённые ранее снимки можно исследовать только вручную с подтверждением происхождения и прав.
- Источник, статус и пределы разрешённого использования перечислены в `research/update_source_registry.json`. Изменение этого списка требует отдельной редакционной проверки.

## Протокол доказательств: manifest.json + исходные байты

Редактор *сам* готовит папку, например `research-output/update-candidates/review-001/`. В ней `manifest.json` и `snapshots/` с подлинными сохранёнными файлами. JSON:

```json
{
  "schema_version": 1,
  "status": "NEEDS_REVIEW",
  "candidates": [{
    "language": "en",
    "canonical_id": null,
    "message_date": null,
    "date_uncertainty": "Дата должна быть установлена редактором",
    "published_at": null,
    "publication_uncertainty": "Дата публикации источника не установлена",
    "source_url": "https://www.medjugorje.hr/en/our-lady-messages-archive",
    "source_kind": "manual_snapshot",
    "source_id": "archive-section-pending-review",
    "snapshot_path": "snapshots/original.html",
    "snapshot_sha256": "<sha256 реальных байтов original.html>",
    "proposed_text": "<текст, вручную сверенный с источником>",
    "proposed_text_sha256": "<sha256 UTF-8 proposed_text>",
    "editorial_status": "needs_review",
    "verified": false,
    "approved": false,
    "attribution_status": "unconfirmed"
  }]
}
```

Это **схема, не готовая публикация**. Никогда не заменяйте `<...>` выдуманными хешами или текстом; `canonical_id: null` — честный статус до сверки типа, даты, визионера и возможных дублей. `published_at` отдельно для **каждого языка** и независимо от `message_date`. Для неизвестных дат должны быть заполнены поля причин неопределённости.

Манифест и snapshot могут содержать охраняемый авторским правом текст: хранить только в закрытом редакционном пакете, **не коммитить исходные байты в публичный GitHub и не загружать в публичный workflow** без правового разрешения.

Проверка только на чтение:

```bash
python -m scripts.update_candidate_gate --bundle research-output/update-candidates/review-001
```

Она сверит семь языков, дубли, идентификаторы, даты, HTTPS и байтовые SHA-256 исходника и предлагаемого текста, а также запрет самостоятельного `approved/verified`. Результат даже при успехе: **REVIEW_ONLY**, `can_import=false`, `can_publish=false`. Совпадение хеша доказывает только целостность того, что сохранили, **не достоверность / правомерность / полноту источника**.

## Append-only проверка перед отдельным редакционным PR

После ручной сверки редактор может подготовить в *другой папке* семь предлагаемых `<lang>.json` и `index.json`, не меняя текущие `data/`:

```bash
python -m scripts.check_append_only_updates --baseline data --candidate research-output/proposed-data
node scripts/check-data.mjs
python -m unittest discover -s tests -v
```

Append-only gate запрещает удаление старых ID, любые изменения ранее существующих записей (включая пробелы, знаки препинания, статус, SHA, source URL), изменение канонической даты/типа/визионера, дубли и невыполненные соответствия между семью языками и общим индексом. **Разрешено добавить ранее отсутствующий языковой перевод к существующему ID или создать новый ID**, если есть соответствующая реальная запись и корректный хеш.

`check-data.mjs` выполняется против текущего каталога `data/`; для предлагаемого каталога сначала нужен отдельный CI/worktree, который проверит кандидат в качестве `data/`. Наличие двух независимых gates не заменяет полной проверки перед выпуском.

Для smoke без изменений:

```bash
python -m scripts.check_append_only_updates --baseline data --candidate data
```

## Как коротко проверить работу

1. Откройте GitHub → **Actions → Independent update safety gates** в Draft PR. Должны быть PASS у unit-тестов и self-comparison `data → data`.
2. В `tests/test_independent_updates.py` проверяются два допустимых сценария: сохранённый источник со сверенным SHA и добавление одного RU-перевода к существующему EN-посланию.
3. В этих же тестах должны быть BLOCKED: изменённый оригинал, подмена предложенного текста, путь `../`, HTTP, дубликат, отсутствие часового пояса, автоматическое `verified`, подмена старого перевода даже с пересчитанным SHA, изменение визионера и исчезновение записи.
4. Откройте **Files changed**: убедитесь, что **ни один** `data/*.json`, `src/`, PWA/workflow публикации и расписания текущих мониторов не изменён.

## Границы и следующий этап

Это полноценный **этап проектирования, реестра источников и защитных тестов**, но **не работающий обновлятор текстов**. Для этапа 2 нужны подтверждённые условия использования каждого актуального полнотекстового источника, независимая сверка языка/типа/визионера, безопасное создание review-only artifacts, а затем — отдельный Draft PR для *ручной* проверки только новых текстов. Никакой автоматический merge или публикация пока не разрешены.
