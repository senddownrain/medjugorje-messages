# Финальный брендинг Medjugorje Messages

Окончательный художественный оригинал — `approved-layout.png` из вложения `1000100157.png`, SHA-256 `f9517bef6dab8ebe0fdc9969bd276170a5758fa7242c0eeadce131329ea0ab2e`. Левая версия светлая, правая тёмная. Прежний JPEG заменён; его история сохранена в git. Повторной генерации, перерисовки лица, храма, линий и нимба нет. В каждой основной версии **12 золотых звёзд**.

## Извлечение и ресурсы

Генератор `scripts/generate-branding.py` копирует RGB художественного оригинала, извлекает прямоугольники `(20,165,716,898)` и `(735,165,1430,898)` и добавляет маску прозрачности по видимому внешнему контуру правой иконки. Маска масштабируется только на границе плитки; внутренние RGB исходника не меняются. Ширина плиток немного меньше высоты: они не растягиваются, а дополняются по бокам прозрачностью до **733×733**. Скругления, все звёзды и нижние линии остаются внутри квадрата.

Установленные иконки ОС не обещают динамическую смену по теме. Стабильные `start_url` и `scope` `/medjugorje-messages/` сохраняют идентичность PWA. После обновления manifest системный launcher может обновить изображение с задержкой; удаление/повторная установка — отдельная проверка, не обязательное действие для обновления приложения.

Шапка использует `isDark`, включая сохранённую тему и системную настройку. При переключении Vue обновляет `src/srcset`, а существующий обработчик темы — три favicon-ссылки, без reload. При недоступном JS HTML имеет рабочий светлый fallback. Все варианты включены в существующий Workbox `injectManifest`; `registerType: prompt`, протокол кеша и `src/sw.js` сохранены. База HTML — `%BASE_URL%`, Vue — `import.meta.env.BASE_URL`.

Повторная подготовка:

```sh
python3 -m pip install -r scripts/requirements-branding.txt
python3 scripts/generate-branding.py
npm run build
```

PNG оптимизированы без квантования основных изображений, WebP сохраняются без потерь после уменьшения. Только отдельный favicon 16 использует три контрастных цвета. Проверка 512/192/96/48/32/16 показана в [предпросмотре](icons-preview.png). При 16 px отдельные звёзды закономерно неразличимы; основные изображения не упрощались.

GitHub Actions запускает ту же регрессию на PR и main. Проверка обновления старого релиза добавлена одним шагом в существующий test-build; deploy не перестроен. После штатного merge существующий `verify-public` проверяет настоящий анонимный HTTPS, ожидаемый SHA `release.json`, все семь опубликованных архивов, темы/иконки, поиск/фильтры и офлайн. Его результат, ссылка deployment и фактический опубликованный SHA фиксируются в финальном отчёте PR #26 и выдаче задачи.

Прямой HTTPS из Codex-среды блокируется proxy CONNECT 403 до достижения `senddownrain.github.io`. Этот отказ не выдаётся за ошибку сайта или успешную проверку. Фактическая публичная проверка выполняется GitHub runner; локальный тест обновления не выдаётся за физический телефон либо публичный upgrade.
