# Утверждённый логотип Medjugorje Messages

Внедрён оригинал из вложения `1000100073.jpg`. Композиция, фон и все **12 звёзд** сохранены: только уменьшение всего изображения, без обрезки, перерисовки или генерации новых деталей. В тёмной теме сохранён светлый фон оригинала.

База совместимости — публичный релиз на удалённой `main`, коммит `4fdf86e` («Publish seven-language Medjugorje reader with C/D search and tested Pages deployment»). Тегов релиза в репозитории на момент работы нет. Сохранены отдельный экран поиска, отложенная загрузка архивов и протокол обновления service worker с подтверждением пользователя. Развёртывание этого изменения не выполнялось. Исходные `data/*.json`, производная модель поиска, тексты и контрольные суммы не изменены.

## Код и воспроизводимость

Обновлены `src/App.vue`, `src/style.css`, `index.html`, `vite.config.js`; в `docs/PWA.md` добавлена ссылка на этот отчёт. В `scripts/check-startup-browser.py` ожидание обновления уточнено: тест ждёт новый документ, поскольку сохранение hash перед обновлением тоже вызывает событие навигации. Это устраняет выявленное в GitHub Actions взаимодействие со старой страницей до её перезагрузки; поведение приложения не изменено. Логотип виден и на 320 px. Размеры в шапке: 32/36/48 CSS px; `srcset` предоставляет 96/192 px. Пустой `alt` исключает повтор озвучивания соседнего названия сайта.

HTML использует `%BASE_URL%`, Vue — `import.meta.env.BASE_URL`. Manifest генерируется `vite-plugin-pwa`: `start_url` и `scope` равны `/medjugorje-messages/`, относительные пути иконок разрешаются внутри этой базы. В публичном релизе PNG и maskable уже были объявлены в manifest; теперь файлы по этим путям содержат утверждённый рисунок. Для другой базы сохранён `SITE_BASE`. В существующий Workbox `injectManifest` добавлены WebP; PNG, ICO и WebP получают новые ревизии кэша при изменении файлов. Стратегия `registerType: prompt` сохранена.

Добавлены `scripts/generate-branding.py` и отдельный `scripts/requirements-branding.txt`. Для повторной подготовки:

```sh
python3 -m pip install -r scripts/requirements-branding.txt
python3 scripts/generate-branding.py
npm run build
```

## Проверка на Android перед следующим развёртыванием

1. Открыть собранную версию по HTTPS на разрешённом тестовом адресе с базой `/medjugorje-messages/`. Проверить шапку в светлой и тёмной теме, затем значок во вкладке Chrome.
2. В Chrome выбрать «Установить приложение» / «Добавить на главный экран». Проверить значок на главном экране и в списке приложений: все 12 звёзд должны оставаться внутри маски, насколько позволяет размер отображения.
3. Запустить PWA с главного экрана. Проверить шапку, закрыть приложение, включить авиарежим и открыть снова: логотип должен сохраниться.
4. Если PWA уже было установлено, проверить обновление существующей установки после получения нового service worker. Системный кэш значка может обновляться с задержкой; отдельно проверить чистую установку после удаления прежнего ярлыка.

Для завершения приёмки владельцу остаётся физическая проверка телефона. Изменение включается в следующее развёртывание после проверки и слияния PR; отдельного разрешения для подготовки файлов не требуется.
